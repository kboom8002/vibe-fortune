## 1. 시나리오 개요

TCO-Vibe Fortune Coach의 사용자 여정은 **매일 반복되는 자기운영 루프**를 중심으로 설계되었습니다. 단순한 운세 콘텐츠 소비가 아니라, **사주 구조(Prior) → 현재 상태(Vibe) → 행동 지침(Action Policy) → 실행 기록(Run Receipt) → 피드백(Recomposition)**의 자기 강화 순환 구조입니다.

### 핵심 사용자 여정 맵

```
┌─────────────────────────────────────────────────────────────┐
│                    사용자 여정 전체 흐름                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [온보딩] ──→ [일일 루프] ──→ [실행 기록] ──→ [주간 리뷰]    │
│     │            ↑                │              │          │
│     │            └────────────────┘              │          │
│     │                                            │          │
│     └─────────────────────────────────→ [월간 분석]          │
│                                            │                │
│                                            ↓                │
│                                      [이력 관리]             │
│                                                             │
│  ════════════ 안전선 게이트 (전 과정 적용) ════════════════   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 대상 사용자

| 유형 | 설명 |
|------|------|
| **1차 타깃** | 비즈니스·창작·건강·관계를 자기 운영하는 고관여 사용자 (창업자, 프리랜서, 크리에이터) |
| **2차 타깃** | AI 자기관리 도구에 관심 있는 사용자, 명리학 팬 중 실용적/안전한 접근을 원하는 사용자 |

## 2. 시나리오 A: 첫 사용자 온보딩

### 개요
신규 사용자가 최초로 서비스에 가입하고 사주 프로필을 설정하는 과정입니다.

### 전제조건
- 인터넷 연결 상태
- 자신의 생년월일시를 알고 있음

### 상세 흐름

```
[1] 랜딩 페이지 접속 (/)
     │
     ├── 서비스 소개 확인
     │   • "사주 × 바이브 × AI = 행동 최적화 지침"
     │   • 안전선 원칙 안내
     │
[2] 회원가입 (/auth/signup)
     │
     ├── 이메일 + 비밀번호 입력
     ├── Supabase Auth를 통한 계정 생성
     │
[3] 로그인 (/auth/login)
     │
     ├── 세션 생성 + 사용자 인증
     │
[4] 온보딩 허브 (/app/onboarding)
     │
     ├── 환영 메시지: "반갑습니다, {이름}님! 당신의 우주적 흐름을 구성할 시간입니다."
     ├── 2단계 온보딩 안내:
     │   • Step 1: 생년월일시 프로필 설정 (활성)
     │   • Step 2: 오늘의 바이브 체크인 (비활성 → Step 1 완료 후 활성)
     ├── 개인정보 보호 및 안전선 원칙 배너 표시
     │
[5] 생년월일시 입력 (/app/onboarding/birth)
     │
     ├── 입력 필드:
     │   • 이름
     │   • 생년월일 (YYYY-MM-DD)
     │   • 출생 시간 (HH:MM, 선택적 — 미입력 시 12:00 기본)
     │   • 타임존 (기본: Asia/Seoul)
     │   • 성별 (male/female/other/unspecified)
     │   • 출생 장소 (선택)
     │
     ├── [저장] 클릭
     │   • 만세력 엔진 즉시 호출
     │   • 사주 팔자 결정론적 계산
     │   • BirthProfile + ChartResult localStorage 저장
     │   • Supabase birth_profiles 테이블 영속화
     │
[6] 일일 바이브 체크인으로 리다이렉트 (/app/daily)
```

### 핵심 UI 상태

| 상태 | 화면 표시 |
|------|----------|
| Step 1 미완료 | 바이브 체크인 버튼 비활성(회색) + "대기 중" |
| Step 1 완료 | 자동으로 `/app/daily`로 이동 |
| 계산 성공 | 사주 차트 미리보기 + 정책 면책 고지 |
| 계산 실패 | 에러 메시지 + 재입력 유도 |

### 안전선 적용

- 생년월일 데이터는 RLS로 보호 → 사용자 본인만 접근 가능
- 안전선 원칙 배너 필수 표시: "입력하시는 사주 정보와 바이브 데이터는 오직 당신만의 행동 지침 처방용으로 임시 연산되며 타인에게 공유되지 않습니다."

## 3. 시나리오 B: 일일 자기운영 루프 (핵심)

### 개요
매일 반복되는 **핵심 사용자 여정**입니다. 현재 컨디션을 입력하고 맞춤형 행동 지침을 받습니다.

### 전제조건
- 로그인 상태
- 생년월일 프로필 설정 완료

### 상세 흐름

```
[1] 일일 바이브 체크인 (/app/daily)
     │
     ├── 사용자 인사: "{이름}님의 현재 몸과 마음 상태를 기록해 주시면,
     │    사주 구조(Prior)와 결합하여 맞춤형 처방을 산출합니다."
     │
     ├── [실시간 상태 진단] 섹션
     │   • 정서가 (Valence): 0-10 슬라이더
     │     ├── 0 = 매우 침울 / 절망
     │     └── 10 = 매우 행복 / 긍정
     │   • 각성도 (Arousal): 0-10 슬라이더
     │     ├── 0 = 무기력 / 졸림
     │     └── 10 = 매우 긴장 / 흥분
     │   • 활력 (Energy): 0-10 슬라이더
     │     ├── 0 = 방전됨 / 극심한 피로
     │     └── 10 = 에너지 넘침
     │   • 집중력 (Focus): 0-10 슬라이더
     │     ├── 0 = 산만함 / 브레인 포그
     │     └── 10 = 고도의 몰입 상태
     │   • 관계 부하 (Social Load): 0-10 슬라이더
     │     ├── 0 = 혼자 있고 싶음
     │     └── 10 = 적극적 소통 가능
     │
     ├── [운영 보드 집중 분야] 섹션 (6개 도메인 중 1개 선택)
     │   • 🔥 비즈니스 & 금융
     │   • 💗 인간관계 & 연애
     │   • 📈 건강 & 에너지
     │   • 🧠 학습 & 연구 & 집필
     │   • ✨ 명성 & 퍼스널 브랜딩
     │   • ⚠️ 위험 관리 & 법률
     │
     ├── [오늘의 주요 이벤트] (선택적 텍스트 입력)
     │   예: "중요한 거래 봉투 협상 예정"
     │
     ├── [오늘의 자기운영 보드 산출] 버튼 클릭
     │
[2] 시스템 처리 (백그라운드)
     │
     ├── 사주 차트 즉시 계산 (결정론적, 클라이언트)
     │   • calculateChart() → 4주 8자
     │   • calculateMajorLuck() → 현재 대운
     │   • calculateAnnualLuck() → 올해 세운
     │   • calculateAllTenGods() → 십신 분석
     │   • analyzeInteractions() → 합충형파해
     │   • analyzeDivineKillers() → 신살 분석
     │
     ├── LLM 포캐스트 비동기 호출 (서버)
     │   • POST /api/forecast/daily
     │   • LangGraph 11-노드 파이프라인 실행
     │   • 실패 시 로컬 폴백 자동 전환
     │
[3] 일일 운영 보드 결과 (/app/result/[id])
     │
     ├── [사주 팔자 (四柱八字)] — 즉시 표시
     │   • 4주 차트: 년주·월주·일주·시주
     │   • 각 주의 천간(天干) + 지지(地支)
     │   • 오행별 컬러 코딩 (木=초록, 火=로즈, 土=앰버, 金=진크, 水=스카이)
     │   • 오행 분포 시각화 (5개 원소별 개수)
     │
     ├── [대운 & 세운] — 즉시 표시
     │   • 현재 대운: 천간·지지 + 시작 나이 ~ 종료 나이
     │   • 올해 세운: 천간·지지 + 오행
     │
     ├── [십신 (十神) 분석] — 즉시 표시
     │   • 4주 각각의 천간·지지에 대한 십신 배치
     │   • 비견/겁재/식신/상관/편재/정재/편관/정관/편인/정인
     │
     ├── [합충형파해 + 신살] — 즉시 표시
     │   • 합충형파해: 삼합/육합/충/형/파/해 건수 및 상세
     │   • 신살: 길신(천을귀인 등) / 흉신(도화살 등) 건수 및 상세
     │
     ├── [AI 분석 중...] — 로딩 스피너 (LLM 처리 중)
     │
     ├── [안전선 준수 알림] — 필요 시 표시
     │   • 경계선 노트 (활력 저하 시 휴식 권고 등)
     │
     ├── [오늘의 총운] — LLM 결과
     │   • 한 줄 요약 + 컨셉 상태 (expansion/consolidation/cleanup)
     │   • 일간(DM) 표시
     │
     ├── [추천 등급] — S/A/B/C 대형 뱃지
     │   • 사주 구조 × 바이브 상태 종합 등급
     │
     ├── [필수 행동 (Do)] — 번호 매긴 액션 리스트
     │   예: "1. 핵심 업무 1가지를 정의하고 완결하기"
     │
     ├── [금지 행동 (Don't)] — 경고 아이콘 리스트
     │   예: "! 사전 조율 없는 대규모 투자 결정이나 구두 확약"
     │
     ├── [세부 분석]
     │   • 개념 분석: 왜 이 컨셉 상태인지 설명
     │   • 행동 조율: 왜 이 지침이 나왔는지 근거 설명
     │   • 보류 사항: 추후로 이연할 행동 목록
     │
     ├── [면책 조항]
     │   "최종 판단과 행동의 책임은 사용자 자신에게 있습니다."
```

### 사용자 의사결정 포인트

| 포인트 | 선택지 | 후속 행동 |
|--------|--------|----------|
| 바이브 체크인 완료 후 | 보드 산출 / 나중에 | 결과 페이지 이동 또는 대기 |
| 결과 확인 후 | 실행 기록 작성 / 다시 진단 / 주간 리뷰 확인 | 해당 페이지 이동 |
| 금지 행동 확인 후 | 수용 / 무시(자유 의지) | Run Receipt에서 "My Judgment"로 기록 가능 |

## 4. 시나리오 C: 실행 기록 및 성찰 (Run Receipt)

### 개요
포캐스트를 받은 후 실제로 어떻게 행동했는지를 기록하고, 자기 성찰을 통해 다음 포캐스트에 피드백하는 과정입니다.

### 전제조건
- 당일 포캐스트를 받은 상태
- 하루가 끝나갈 때 (저녁~밤 시간대 권장)

### 상세 흐름

```
[1] 실행 기록 페이지 진입 (/app/run-receipt/[forecastId])
     │
     ├── 헤더: "오늘의 실행 기록 (Run Receipt)"
     ├── 설명: "보드의 지침을 어떻게 실행하고 조율했는지 기록하여
     │    나만의 최적화 루프를 만듭니다."
     │
[2] 필수 입력
     │
     ├── [실제 내가 행동한 것 (What I Did)] * 필수
     │   "지침에 맞춰 오늘 어떤 결정을 내리고 실행했는지 요약해 주세요"
     │
[3] 선택 입력 (격자 레이아웃)
     │
     ├── [그 행동을 선택한 이유 (Why I Chose It)]
     │   "의사결정의 직관 혹은 상황적 근거"
     │
     ├── [보류하거나 지연시킨 행동 (What I Deferred)]
     │   "충동적 확장이나 다음으로 넘긴 과제"
     │
     ├── [AI의 어떤 조언이 도움되었나 (What AI Helped)]
     │   예: "과로 방지 및 경계 경고 리마인더"
     │
     ├── [지침과 다른 나의 주관적 판단 (My Judgment)]
     │   "상황에 따른 나만의 독자적 의사결정"
     │
     ├── [오늘 하루 배운 교훈 (What I Learned)]
     │   "경험을 통해 발견한 나만의 패턴"
     │
     ├── [다음 단계 액션 (Next Action)]
     │   "내일의 운영에 연계할 다짐"
     │
[4] [오늘의 실행 일지 기록 완료] 버튼 클릭
     │
     ├── RunReceipt 객체 생성 (UUID, timestamp)
     ├── localStorage 저장 (오프라인 대응)
     ├── Supabase run_receipts 테이블 영속화 (RLS)
     │
[5] 이력 페이지로 리다이렉트 (/app/history)
```

### 핵심 설계 원칙

> ⚠️ **비실행을 비난하지 않는다**: 사용자가 지침을 따르지 않았을 때 그것을 비판하거나 수치심을 주지 않습니다. 비실행은 "계획이 너무 컸다"는 신호로 처리하며, 다음 포캐스트에서 범위를 축소합니다.

## 5. 시나리오 D: 주간 운영 리뷰

### 개요
7일간의 일일 포캐스트와 실행 기록을 집계하여 주간 단위의 통합 리뷰를 제공합니다.

### 전제조건
- 최소 1일 이상의 일일 포캐스트 이력 (7일 누적 시 최적)

### 상세 흐름

```
[1] 주간 운영 리뷰 페이지 접속 (/app/weekly)
     │
[2] 시스템 자동 집계
     │
     ├── GET /api/forecast/weekly 호출
     ├── 최근 7일 ForecastOutput + RunReceipt 데이터 수집
     ├── 주간 패턴 분석
     │
[3] 결과 표시
     │
     ├── [주간 총론]
     │   "이번 주는 확장보다는 정리와 점검에 적합한 주간입니다."
     │
     ├── [핵심 컨셉 상태]
     │   • 컨셉 이름 (예: "정리")
     │   • 상태 (consolidation)
     │   • 신뢰도 (82%)
     │
     ├── [갭 분석]
     │   "근거(Evidence) 확보 수준이 낮습니다. 데이터 기반 의사결정을 강화하세요."
     │
     ├── [목표 3분류] (3열 그리드)
     │   • 📗 근거 확보 목표: "고객 피드백 3건 이상 수집"
     │   • 📙 경계선 목표: "과도한 야근 주의"
     │   • 📕 전환 목표: "리드 2건 → 미팅 전환"
     │
     ├── [주간 리스크 궤적] (7열 시각화)
     │   월(low) → 화(medium) → 수(medium) → 목(high) → 금(medium) → 토(low) → 일(low)
     │   • low = 초록 화살표(↘)
     │   • medium = 노란 대시(—)
     │   • high = 빨간 화살표(↗)
     │
     ├── [행동 정책]
     │   • 필수: "기존 프로젝트 마감 우선"
     │   • 금지: "신규 대규모 투자 결정"
     │
     ├── [성찰 질문]
     │   "지난 주 보류했던 의사결정 중, 이번 주에 처리할 수 있는 것은 무엇인가요?"
```

### 데이터 부족 시 동작

| 상태 | 동작 |
|------|------|
| 0일 데이터 | 캐시된 이전 주간 리뷰 표시 또는 안내 메시지 |
| 1-3일 데이터 | 부분 분석 + "데이터 부족" 경고 |
| 4-7일 데이터 | 전체 분석 |

## 8. 시나리오 G: 안전선 발동 (Safety Trigger)

### 개요
사용자 입력 또는 시스템 출력에서 위험 패턴이 감지될 때의 처리 흐름입니다.

### 안전 분류 및 시나리오

#### G-1: 자해/자살 관련 입력 (S3 Critical)

```
사용자 입력: "살기 싫다" / "자해하고 싶다"
     │
     ├── InputSafetyGate 감지
     ├── 즉시 차단 (일반 포캐스트 생성 중단)
     ├── 위기 안내 메시지 표시:
     │   "현재 많이 힘드신 것 같습니다.
     │    전문 상담을 받으시는 것을 강력히 권장합니다.
     │    자살예방상담전화: 1393
     │    정신건강위기상담전화: 1577-0199"
     ├── SafetyEvent 로깅 (safetyFlags: ["self_harm_detected"])
```

#### G-2: 의료/법률/투자 최종 판단 요청 (S2 High-risk)

```
사용자 입력: "이 주식에 전 재산을 투자해도 될까?"
     │
     ├── InputSafetyGate 감지
     ├── 리다이렉트 처리:
     │   일반 포캐스트 생성 + 경계선 노트 추가
     │   "⚠️ 투자 결정은 전문 재무 상담사와 상의하시기 바랍니다.
     │    본 서비스는 투자 판단을 제공하지 않습니다."
     ├── boundaryNotes에 경고 추가
```

#### G-3: 관계 조작 의도 (S2 High-risk)

```
사용자 입력: "상대방을 질투하게 만들 방법을 알려줘"
     │
     ├── InputSafetyGate 감지
     ├── 차단 + 리프레이밍:
     │   "관계에서 진정한 신뢰는 조작이 아닌 진솔한 소통에서 옵니다.
     │    오늘의 지침은 자기 성장에 초점을 맞추겠습니다."
     ├── safetyFlags: ["relationship_manipulation_blocked"]
```

#### G-4: 결정론적 예측 요구 (S1 Boundary-needed)

```
사용자 입력: "내일 반드시 좋은 일이 생기나요?"
     │
     ├── SafetyBoundaryReviewer 적용
     ├── 리프레이밍:
     │   "사주 구조는 확정된 미래가 아닌 구조적 경향을 나타냅니다.
     │    오늘의 오행 흐름을 고려한 행동 지침을 제안드립니다."
     ├── 모든 출력에서 "반드시", "무조건", "확정" 등 표현 제거
```

#### G-5: 공포/불안 증폭 요청 (S1 Boundary-needed)

```
사용자 입력: "올해 엄청 나쁜 운이라던데 큰 사고가 나는 거 아닌가요?"
     │
     ├── SafetyBoundaryReviewer 적용
     ├── 차분한 재해석:
     │   "충(沖)이 있는 해라고 해서 반드시 부정적인 것은 아닙니다.
     │    변화의 에너지가 강한 시기로, 준비된 변화를 주도할 수 있습니다.
     │    오늘의 행동 지침에서 리스크 관리 방법을 확인하세요."
     ├── 공포 증폭 표현 제거 + 행동 중심 조언으로 전환
```

## 10. 시나리오 I: 재구성 피드백 루프 (Recomposition)

### 개요
여러 날에 걸친 Run Receipt 데이터를 축적하여, 시스템이 사용자의 행동 패턴을 학습하고 향후 포캐스트를 자동 조정하는 장기 시나리오입니다.

### 패턴 감지 및 자동 조정

| 감지 패턴 | 신호 | 다음 포캐스트 조정 |
|----------|------|-------------------|
| **반복적 비실행** | 필수 행동을 3회 연속 미이행 | 범위 축소 → 단일 액션 정책으로 전환 |
| **반복적 과로** | 높은 각성도 + 적은 수면 + 많은 액션 | Recovery 모드 강제 적용 |
| **경계선 개선** | 경계 행동을 반복적으로 이행 | overclaim/scopeLeak 리스크 하향 |
| **관계 압박** | 반복적인 장문 관계 질문 | 따뜻함(Warmth) + 자율성 경계 강화 |
| **근거 확보 행동** | 시장 검증 로그 기록 | 확장(Expansion) 허용 + 경계 유지 |

### 재구성 피드백 항목

```
Recomposition 엔진 출력:
{
  executionAlignment: 0.72,      // 실행 일치도 (0-1)
  independentJudgmentRate: 0.35, // 독자적 판단 비율
  deferralPattern: ["대규모 투자", "신규 프로젝트"],  // 보류 패턴
  learningAccumulation: [        // 누적 교훈
    "화요일 오후 집중력 최고",
    "금요일 큰 결정 보류가 효과적"
  ],
  nextPolicyBias: "consolidation", // 다음 포캐스트 기본 바이어스
  scopeReduction: true             // 범위 축소 필요 여부
}
```

### 시간대별 피드백 적용

| 주기 | 적용 방식 |
|------|----------|
| **일일** | 전일 RunReceipt → 당일 ContextTensor에 반영 |
| **주간** | 7일 패턴 분석 → 주간 리뷰 내 리스크 트렌드 및 컨셉 갭 반영 |
| **월간** | 30일 포트폴리오 → 컨셉/리스크 포트폴리오, 30일 재구성 목표 설정 |

## 11. 시나리오 J: 오프라인/폴백 상황

### 개요
LLM API가 불가용하거나 네트워크 연결이 불안정할 때의 사용자 경험입니다.

### 폴백 단계

```
[1] LLM API 호출 시도
     │
     ├── 성공 → 정상 포캐스트 표시
     │
     ├── 실패 (1차) → 지수 백오프 재시도
     │
     ├── 실패 (2차) → 서킷 브레이커 확인
     │
     ├── 실패 (3차) → 로컬 폴백 전환
     │
[2] 로컬 폴백 포캐스트 생성
     │
     ├── 사주 차트 계산 (항상 가능 — 결정론적, 클라이언트)
     │   • 4주 8자 ✅
     │   • 대운/세운 ✅
     │   • 십신 분석 ✅
     │   • 합충형파해 ✅
     │   • 신살 분석 ✅
     │
     ├── Vibe 기반 기본 등급 산정
     │   • (energy + focus + valence) / 3 → S/A/B/C 등급
     │
     ├── 오행 기반 기본 행동 지침
     │   • 木: "새로운 아이디어를 적극 제안"
     │   • 기타: "기존 계획의 완성도를 높이기"
     │
     ├── 에너지 연동 경계선 노트
     │   • energy < 4: "활력이 낮은 상태입니다. 반드시 2시간 이상 휴식을 확보하세요."
     │
[3] 사용자 경험
     │
     ├── 사주 차트 분석은 완전히 동작 (지연 없음)
     ├── AI 총운/행동 지침은 기본 버전으로 표시
     ├── "AI 서버 연결 없이 기본 분석을 제공합니다" 안내 (선택)
```

## 14. 경계 케이스 및 에러 처리

### 14.1 입력 관련

| 케이스 | 처리 |
|--------|------|
| 출생 시간 미입력 | 12:00(정오) 기본값 + `BIRTH_TIME_APPROXIMATE` 경고 |
| 무효한 날짜 | 유효성 검증 에러 + 재입력 유도 |
| 타임존 미입력 | `Asia/Seoul` 기본값 |
| 성별 미지정 | `unspecified` → 대운 방향 추정 시 양순 기본 + `GENDER_UNSPECIFIED` 경고 |
| 빈 바이브 체크인 | 모든 값 5(중간) 기본값 적용 |

### 14.2 시스템 관련

| 케이스 | 처리 |
|--------|------|
| LLM API 타임아웃 | 지수 백오프 재시도 → 로컬 폴백 |
| LLM 연속 실패 | 서킷 브레이커 작동 → 일정 시간 후 재시도 |
| Supabase 연결 실패 | localStorage 캐시 활용 + 재연결 시 동기화 |
| 스키마 검증 실패 | Zod 에러 + 사용자에게 "분석 요청 중 오류 발생" 표시 |
| 사주 계산 예외 | try-catch + `console.warn` + 해당 섹션 생략 (나머지 정상 표시) |

### 14.3 데이터 관련

| 케이스 | 처리 |
|--------|------|
| 프로필 미설정 상태 접근 | `/app/onboarding`으로 리다이렉트 |
| 주간/월간 데이터 부족 | 부분 분석 + 경고 / 목 데이터 기반 기본 레이아웃 |
| localStorage 용량 초과 | 오래된 캐시 자동 정리 |
| RLS 권한 오류 | 로그아웃 → 재로그인 유도 |
